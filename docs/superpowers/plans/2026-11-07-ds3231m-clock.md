# DS3231M RTC Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the STM32L010F4 internal RTC/LSE time source with DS3231M on a dedicated PA5/PA6 software I2C bus and document complete wiring.

**Architecture:** Put BCD/calendar validation and register packing in a small header that can be host-tested. Keep GPIO transactions and DS3231M initialization in `main.c`, route existing clock display and edit state through the external RTC, and leave OLED on PA9/PA10.

**Tech Stack:** C11 host tests, arm-none-eabi-gcc Cortex-M0+, software I2C, DS3231M register interface.

**Spec:** `docs/superpowers/specs/2026-11-07-ds3231m-clock-design.md`

## Global Constraints

- DS3231M is the sole clock/calendar source for display, PA4 editing, and PA1 one-second toggling.
- OLED remains on PA9/PA10; DS3231M uses PA5=SCL and PA6=SDA.
- DS3231M address is 0x68; DS bus pullups are 4.7 kOhm to 3.3 V.
- On OSF, initialize 2026-10-18 16:20:00 with Sunday=1, then clear OSF.
- PA4 edit values are cached and committed once when leaving seconds setting.
- Do not claim physical validation if CMSIS-DAP cannot connect.

## Review Focus

- Invalid BCD or out-of-range DS calendar data must be rejected without feeding corrupt values to display; test invalid digits and range bounds.
- DS3231M NACK must fail the read/write transaction and preserve the prior displayed time; test return handling at the driver boundary by inspection and hardware ACK reporting.
- First-start OSF handling must set the chosen preset and clear OSF; host test checks encoded preset bytes, driver inspection checks status bit handling.
- Sequential calendar write must begin at seconds and include all remaining fields in one burst; inspect transfer sequence because the host tests cannot emulate physical I2C.
- 8-SO wiring must be unambiguous; verify the package map against the supplied datasheet and README table.
